# Session browsing and fidelity audit

## Context modes

Cross-agent conversion creates a separate historical-text session. It does not turn another provider's encrypted or signed reasoning into native thinking state.

| Mode | Preserved in the new context | Omitted or shortened |
| --- | --- | --- |
| Balanced | Dialogue, tool inputs, project instructions/file changes, errors and write results | Long successful read-only results are shortened; thinking, signatures, binary attachments and runtime metadata remain in the source |
| Complete text | Dialogue and complete tool inputs/results, project instructions/file changes | Thinking, signatures, binary attachments and runtime metadata remain in the source |
| Messages only | User and assistant message text, readable compaction notes | Tools/results and additional runtime context are omitted |

Readable thinking summaries are ordinary text that another model could read if quoted; omitting them here is a context-selection choice. Encrypted reasoning and provider signatures cannot be treated as the other provider’s native thinking state. The original source JSONL remains unchanged in Grove. Existing previously converted sessions are not rewritten. None of the modes replays a foreign tool call as a live action. Errors are useful evidence of failed attempts, so Balanced retains them instead of guessing that they are irrelevant. Messages only is the explicit lower-context alternative.

These modes are product choices, not provider-prescribed conversion formats. OpenAI documents replaying native reasoning items for its own continuation protocol ([reasoning guide](https://developers.openai.com/api/docs/guides/reasoning)); Claude documents preserving signed thinking blocks in its own tool-use protocol ([extended thinking](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)). Neither provides a cross-provider decoder. Claude's official session functions are file operations ([session API](https://code.claude.com/docs/en/agent-sdk/sessions)); Grove uses the pinned SDK for native projection and forks. Codex's central history storage does not eliminate the runtime working directory ([app-server](https://learn.chatgpt.com/docs/app-server)).

## Native fidelity evidence

- Two complete native Codex samples: native New branch versus Grove Fork → Activate; 5/6 projected items and 15/16 model-history records matched, including world state and base instructions. Generated identity/path fields are intentionally rebound.
- Codex synthetic activation: read/resume, deactivate/reactivate, compaction enabled/disabled all passed.
- Two downloaded Claude samples: 14,261,113 source bytes and 11 completed checkpoints; projected messages and native fork records matched the official SDK after normalizing generated identity/timestamp fields. Original files remained unchanged.
- Cross-agent modes: all three reopened in native Codex without a model turn; reverse conversions were read through Claude's official SDK with each selected text entry retained.
- No model requests were submitted. These checks establish record/reader equivalence for the tested versions, not identical future model outputs, hidden requests or external files. Codex: `0.155.0-alpha.16.3`; Claude Agent SDK: `0.3.283`.

## Runtime measurements

Current reproducible measurements use `pnpm bench:git` and `pnpm bench:store`. Earlier provider-specific measurements and scripts were retired with that backend. CPU, memory and I/O measurements are resource proxies, not direct energy measurements.

## Interaction validation

The browser fixture covers 20 projects, default one-week session folding, count-based folding, an empty hidden Ungrouped entry, stable node-to-transcript scrolling, before-node Fork, three compact context modes, folder selection, actual isolated activation, sync without a modal and bounded progress layout.

A root cannot Fork before itself. A later Node can Fork only when its preceding context ends at a completed native turn. Activate remains an endpoint action. Pending labels use graph depth and sibling order (`1`, `2.1`, `2.2`, `3.1`).

Live synthetic Teracloud verification also passed upload, lazy download, native activation, continuation from another device, project moves and idle/no-request checks. Its disposable child folder was deleted afterward. Existing Archive behavior was exercised in that isolated fixture; Trash was not enabled in 0.12; its implemented 0.13 lifecycle is described in [Trash design](trash-design.md).

## Environment

The local npm command was absent and the original lock referenced three dependencies too new for the configured pnpm release-age policy. npm was installed alongside the existing Node installation; the lock was re-resolved under the unchanged policy. The pinned Claude Agent SDK remains `0.3.283`. Missing dependencies now produce an immediate install hint instead of a 30-second worker timeout.
