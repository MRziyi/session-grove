# Session fidelity and operation (0.9)

## Start and stop

Run `pnpm install` once, then `pnpm start`. `pnpm status` reports the matching
library's PID and URL; `pnpm stop` requests shutdown through an authenticated
loopback endpoint. Pass the same `--data-dir` to all three commands when using
a non-default library. Ctrl+C also stops the foreground server. For `pnpm dev`,
Ctrl+C stops the Node watcher as well; a watcher left open can restart on edits.

Shutdown stops scheduling work and cancels ordinary WebDAV requests. It allows
up to ten seconds for pending work. A settings migration retains its private
recovery journal if it exceeds that deadline. Native writes remain synchronous
and journalled. `server.json` is owner-only and records the port and an instance
identity; stop never kills an arbitrary process merely because it holds a port.

## Native history

Codex paginated forks with a native parent and no cutoff ordinal are linked by
their native identity. An exact ordered prefix is shared when it can be verified.
If the parent was subsequently rewritten or compacted, the family relationship
is retained with `prefixUnavailable`; unmatched chats are not deduplicated.
Archived ancestors participate without changing their archive or activation state.
Existing project membership and named organization remain authoritative.

Claude projection and native fork materialization use the pinned official
`@anthropic-ai/claude-agent-sdk` file-only functions in a reusable worker. These
functions resolve parent chains, compaction, queued messages and synthetic
attachment messages. The worker never calls `query`, launches an agent, or sends
a model request. Grove retains the original JSONL separately from that projection.

The official fork creates fresh message UUIDs and parent pointers and deliberately
starts without file undo history. This is the behavior Grove follows. Message
content equivalence does not imply identical IDs, dynamic instructions, model
state, model responses, credentials, permissions or external files.

Claude companion files are captured with SHA-256 checksums in immutable revisions
(32 MiB and 2,000 files per snapshot limit). Restoration validates paths and bytes,
backs up each destination and refuses to overwrite a differing file. Native-style
forks follow the SDK's companion/undo semantics. Files outside the session companion
directory, including repository contents and absolute references embedded in prose,
are not relocated or reconstructed.

Official behavior: [Anthropic's session browser guide](https://platform.claude.com/cookbook/claude-agent-sdk-05-building-a-session-browser).

## Cross-agent continuation

Select a session endpoint, then **Activate as…**. The other agent receives a new,
separate session in the same project. The source revision remains immutable.
The preview is bound to the source hash, revision, target, mode and destination.
Native activation still requires the target agent to be closed.

| Mode | Context sent to the target |
| --- | --- |
| Full history | Exact source JSONL embedded as a historical archive with provenance and a hash. Foreign instructions remain historical data; tool calls and encrypted thinking are not executed or represented as native target capabilities. |
| Lean context | Conversation text and tool calls/results. Read/Glob/Grep, explicitly named read-only tools, and simple allowlisted shell reads (cat/head/tail/ls/pwd/wc/rg/grep/git status/diff/show/log, with no chaining, redirects or substitutions) over 2,000 characters keep their first 900 and last 300 characters plus a hash and omission count. Errors, writes, other shell results and unknown tools keep their complete output. Thinking and transport records remain in the source; Claude uses its native selected conversation chain. |

This is deterministic pruning, not an LLM-generated summary. Grove does not invent
decisions or silently summarize the user's requirements. Large shell output may
still make lean mode expensive. Token counts are estimates; target configuration
informs the warning. Full mode preserves log bytes, not external file contents or
an equivalent model context. Context compaction settings from the source do not
become target runtime settings. Generated import receipts are explicitly labelled.

## Measurements and checks

Personal-data checks are opt-in and report counts, timings and hashes, not bodies:

```sh
pnpm test
node scripts/claude-smoke.js /path/to/claude-home
node scripts/codex-smoke.js /path/to/current/codex
node scripts/conversion-smoke.js /path/to/current/codex
```

The September 2026 local audit covered 32 Claude sessions (188.8 MB) and 111 fork
checkpoints, including full fork-record comparison after normalizing generated IDs/timestamps, and exercised full/lean conversions using Codex
0.155.0-alpha.16.3 `thread/read` and `thread/resume`, with zero model turns.

Initial local import on that machine fell from a historical 57.2 seconds to 30.7
seconds: discovery 4.4 s, SQLite import 16.4 s, family inference 9.9 s. A warm
unchanged refresh was about 21 ms; a capture with one changed session about 98 ms.
Appending to a known session no longer reruns whole-library family inference.
`capture-phase` diagnostic events expose all four phases on each device.

The largest tested tree has 49 paths, 101 graph nodes and 2,082 distinct chats.
Cold projection was about 3.1–3.3 seconds, warm projection below 1 ms. Its 20.5 MB
expanded graph becomes 7.5 MB with shared message bodies and 2.2 MB over gzip.
Only one full tree is cached at a time. **Fit tree** provides a whole-tree overview; zoom can go down to 2%. Peak process RSS in these large-history
checks was still approximately 1.2–1.4 GB: cold parsing is a remaining cost, not a
promise of constant memory or instantaneous loading.

WebDAV remains a content-addressed per-record protocol. First upload can require
many requests even after local import is fast. Successful immutable uploads are
checkpointed during transfer and on failure, so retries can skip known objects. Downloads also persist only hash-verified objects in bounded batches, without exposing a partial session.
Publication happens after dependencies; interrupted uploads do not publish partial
project heads. This release does not replace the protocol with incompatible packs.

Offline maintenance uses `scripts/maintain-library.js`, requires a stopped service,
and creates an owner-only SQLite snapshot before applying a tree/project plan.
Project assignment preserves raw records, native files and archive flags.
