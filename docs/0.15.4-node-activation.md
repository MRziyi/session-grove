# 0.15.4: activation across compaction windows

Activating a node copies its path prefix through that node. A compaction following its final message belongs to the next window and is excluded, even when there is no completed-turn checkpoint before that compaction. Earlier enabled compactions remain in the native history; disabling one removes that boundary so the client uses the preceding history. Preview and materialization use the same cutoff and compaction policy.

Zeroed native usage counters are not evidence of an empty context. The preview falls back to the readable summary, retained messages and subsequent text. An opaque native compaction without a later usable token count is labelled unestimable rather than displaying its readable portion as the entire context. Text-based estimates remain approximate.

Fresh activation and tool conversion create independent native IDs and files while clients remain running. Codex rows are added in a SQLite transaction without checkpointing or backing up the entire live database. Shared JSONL indexes receive appended hints; Claude's shared picker cache is not rewritten for a new session. Existing-file edits, removal and legacy backup recovery retain their protections. File collisions, unsupported schemas, unresolved tool calls and missing attachments remain explicit failures.

Information and Language use the navigation background, with hover feedback retained.
