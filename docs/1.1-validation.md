# 1.1 validation matrix

This matrix is defined before executing the 1.1 acceptance run. The local acceptance corpus is a consistent SQLite backup of the user's actual library (226 branch records, 19 projects at capture), including its recovery files. Personal transcripts and raw evidence remain outside Git. Mutation tests use that corpus and real native transcript bytes in disposable client homes; the running workspace is checked separately. Synthetic regressions supplement, rather than replace, this corpus.

| Area | Valid cases | Rejected / exceptional cases | Required invariants |
| --- | --- | --- | --- |
| Tree read/navigation | Every live tree and archived projection; every path, root/internal/leaf node; shared prefix, mixed tools, long transcripts; search and folded projects | Missing tree/path, stale response after navigation, empty projection | Prefix/order/labels unchanged; no sibling leakage; camera and transcript focus agree |
| Organization | Rename session/node/project; combine and dissolve continuous ranges; move whole tree to project/new project/Ungrouped, including Current Active drag; multi-selection | Empty names, stale version, missing target, archived target, discontinuous ranges, crossing fork boundary, drop on same project/outside target/Escape | Whole tree moves together, including archived siblings; activation unchanged; shared labels stay shared |
| Activation | Root, every completed intermediate node, endpoint; same tool, alternate directory, repeat activation, deactivation; multiple native copies | Unfinished turn/tool call, stale node/version, nonexistent directory, unavailable context, busy native file, incompatible format | Original bytes retained; exact selected prefix; no unwanted suffix; failed operation leaves recoverable state |
| Activate as | Codex ↔ Claude text conversion; all three retention modes, root/internal/leaf | Same/invalid target, stale preview, missing directory, unavailable client | Explicit new identity and lineage; original retained; conversion boundaries reported |
| Client links | Official installed Codex VS Code handler and CLI resume arguments; restored/activated identity | Claude extension absent; missing native copy | Exact native ID and working directory; no fabricated installed capability |
| Client archive | Individual branch and whole family; same project categories; native copy changed since capture; shared native prefix | Busy file, other active copy, archive API error, corrupt prior recovery | Recovery verified before removal; graph ancestry/layout retained; active siblings preserved |
| Trash | Endpoint, whole tree, multiple trees/projects, archived branch; retry leftover native cleanup | Active session, intermediate node, stale graph, unknown ID, duplicate selection, busy/changed copy | Selected paths only; kept prefixes retained; no reimport resurrection; recovery precedes deletion |
| Restore | Whole tree, one sibling, parent before/after child, separate recovery entries, multiple projects; already-restored broken AR/XR lineage | Expired/deleted/corrupt backup, duplicate restore, missing project, partial batch failure | New selected identities; shared ancestor reunification; exact bytes and labels; no activation; navigate/flash restored rows twice |
| Discard changes | Rename/node/layout/move/context/archive/transcript/new session; one/multiple trees; active prerequisite confirmation | Stale selection/baseline, concurrent update/sync, declined confirmation, native deactivation failure | Baseline restored; unrelated work retained; new content backed up; progress visible; no silent loss |
| Synchronization | Pending selection and summaries; Pull/Push with local disposable Git remote; unchanged repeat; local edits during transfer | Conflict, offline/error, stale metadata, interrupted operation | Private actual corpus never published; trash/restored graph survives round trip |
| Observability/performance | Recovery size and per-phase latency, large graph load, activation/deactivation, discard, cleanup; event-loop heartbeat and SSE | Partial failure, disconnect/reload, duplicate clicks, concurrent mutation | Actual progress in lower-right task panel; persistent actionable failure; no fabricated percentages |
| UI/accessibility | Compact pending menu; title/category same line, checkbox above date; stable select/deselect position; category selection; desktop/narrow screen | Empty search/selection, overflow, keyboard/Escape, reduced motion | Application typography/colors/spacing; no overlapping controls; usable focus and labels |

Execution results and measured limits are appended after the acceptance runs. “Passed” must identify its environment; unavailable external clients are not counted as exercised.

## Local results (2026-09-30)

The full real-corpus audit passed **246 checks** with no failures:

- Read all **73 visible trees** from the 226-record, 19-project snapshot; preview root/middle/endpoint positions for every visible path. The largest original family has **42 paths**.
- Materialize and deactivate **30 real node prefixes**, including repeat activation and exact ordered-message comparisons. Exercise whole-family moves, stale graph rejection, node naming and all three conversion modes on representative real families.
- Trash and restore all 73 original families, with **180 paths** after test continuations, then run reclamation and reread every recovered tree. Compare full ordered message digests, path counts and existing node names; restored identities have no native activation.
- Repair the previously detached AR recovery into its recorded XR family without changing transcript bytes. Independently test both parent/child recovery orders, separate sibling recoveries, project moves during Trash, and rejection of title-only ancestry guesses.

Additional actual-corpus runs passed:

| --- | --- |

| Discard and local Git | 6 scenarios: full metadata/layout/move/fork rollback on 3- and 42-path trees; cancelled Trash restores original identities; active prerequisite confirmation; recoverable never-synced real history; local Git Push/Pull/Trash/Restore round trip |
| Official installed Codex app-server | Root, middle and endpoint: read, paginated items, resume, deactivate, reactivate, client archive, removal and recovery; shared family retained; **zero model requests** |

The official-client run found an additional failure after a settings-only append: reactivation lost the intermediate-node boundary permission. This is fixed and covered by both a targeted regression and all three official-client round trips. The paginated official client exposes history through `thread/items/list`; an empty legacy `thread.turns` array is not treated as lost history.

## Performance observations

Measurements are local observations, not cross-machine guarantees. CPU profiles and raw reports remain in private local test output.

- Largest compressed recovery: approximately **139 MB**; measured restore approximately **1.2–1.3 s**. The pipeline reports read/decompression, graph parse, verification counts, record-write counts and relationship restoration. Individual synchronous graph/JSON sections can still occupy the server for roughly a second on the largest corpus item; the browser has already received the phase and remains responsive.
- Native benchmark across the same **30 real prefixes**: approximately **59 s → 15 s** cumulative after narrowing capture/journals and separating immutable baselines. Profiling identified repeated serialization of the entire instance baseline array as the largest avoidable cost.
- Official root/middle/endpoint round trips each took approximately **3.7–4.1 s**, including multiple app-server starts, read/resume, archive/reactivation, native removal and recovery. These operations expose actual phases rather than an invented percentage.
- Discard of the **42-path** family took approximately **8.4 s**, dominated by preserving its recovery copy. Its backup stages and real record counts are forwarded to the task panel.

The mutation corpus is a consistent copy of the user's real records and recovery files, not generated conversation examples. Native mutation uses disposable homes with the installed official executable. Browser mutation uses the same real corpus in a local test server. Live-library repair and deployment are checked separately. Claude's absent interactive extension is not claimed as tested. Platform CI results are tracked with the release; these local measurements were made on macOS.

The final local automated suite passed **259 tests**, with one platform-specific skip and no failures; the three standard browser suites passed. The additional lineage migration regressions verify byte preservation, retained shared annotations, idempotency and refusal to join unrelated histories with identical names.


## Live installation check

The running personal library was backed up before the 1.1.0 restart. The previously detached recovery was repaired in place: **three paths and five graph nodes** now share one family. All restored transcript hashes match the pre-upgrade backup. A read-only Chrome pass selected every real graph node with no browser errors. The existing active Codex URI was dispatched through the system to VS Code; this verifies URI dispatch and identity, not an automated assertion about the extension's rendered editor contents.

To repeat the private-corpus runs, pass a consistent SQLite library snapshot (including `device.json` and its `trash` directory) and a fresh output directory to `scripts/real-workspace-audit.js`, `scripts/real-workspace-browser.js`, `scripts/real-client-acceptance.js`, `scripts/real-discard-acceptance.js`, and `scripts/real-http-acceptance.js`. The source is only read. These explicit scripts are not run by public CI and never upload the supplied corpus.
