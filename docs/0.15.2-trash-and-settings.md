# 0.15.2: settings, selection and recovery

Settings cards use equal 12px internal gutters, overriding the generic dialog heading margin. Repository verification/status and Modify share one heading row. Language is an En/中 button beside Information. Read-only dialogs use the top close control and backdrop dismissal; Information omits diagnostic tooling.

Verify and connect checks the SSH remote before persisting settings. It uses the user's SSH agent/configuration, not a fixed private-key path. Authentication, host-key, repository-access and network failures receive distinct messages; failed checks preserve the previous repository.

The main list and detail rail use one deterministic project/session ordering. Back returns to the project most recently browsed; Current Active retains its tool-category highlight. Any selection changes Select all to Deselect. Group checkboxes select the group's sessions, including folded rows; transcript selection uses the same Deselect term. The editor separator is 10px, matching card edge spacing, while retaining resizing and ribbons.

## Trash copy types

- Client copies are remaining native files for Grove-discarded sessions, plus archived client copies discovered during Update. They are not themselves the expiring recovery backup.
- Recovery copies are local snapshots. Restore creates a new Grove session. Delete now removes the selected local backup immediately; expiry does the same at its configured deadline. Neither action erases Git history.

The Trash list has trailing checkboxes and toolbar actions for move to recovery, restore and delete now. Selection and failures are per copy. Native copy conversion verifies an existing backup or captures current history into a new backup before removing native files. It includes Claude companions, checks for file changes and retains Codex files still referenced by another native history. One archived instance can be removed without discarding another active instance of the same Grove session.

Codex conversion archives through its native API when needed, then checks only the selected file for open handles. It does not reject all operations merely because another Codex/IDE process exists. Append-only Codex title hints are left intact while the canonical thread row and selected body are removed. Claude has no equivalent archive integration here: Claude processes must be closed before modifying its file/index/companion set. No Claude executable is needed to manage retained copies when Claude is not running.

This restriction is Grove's write-safety policy, not a universal requirement that an IDE exit. A specific file may still be held open, changed concurrently, referenced by a native fork, or blocked by filesystem/database permissions. The UI retains that copy and reports the reason.

Validation includes recovery from changed native logs, corrupt-old-backup replacement, selective permanent deletion, HTTP batch restoration, preservation of another active copy and Claude companion recovery. `scripts/trash-native-smoke.js` uses a disposable native home and the installed Codex archive API, keeps another Codex process alive, removes the selected copy and restores its backup. It submits no model requests and never acts on personal sessions.

## Project dragging and native client refresh

Project-list rows can be dragged to a project group or a project in the sidebar, including an empty project. Dragging a selected row moves the selected sessions together; dragging an unselected row moves only that row. The list and sidebar scroll near their upper and lower edges. Hovering over Older projects expands that section. Existing Move to project remains available.

An activation-created empty endpoint is a graph placeholder. Once its native continuation is deactivated, Grove no longer draws that zero-chat node; the source conversation and captured native identity remain intact. A continuation with new chats, and a deliberately created fork, retain their nodes.

Codex's public `thread/archive` API sends lifecycle notifications on its own app-server connection, not to a separate VS Code app-server. The installed VS Code extension (26.917.62051) additionally coordinates its windows over `$CODEX_HOME/ipc/ipc.sock`: little-endian length-prefixed JSON, initialized clients, and versioned `thread-archived` (2) / `thread-unarchived` (1) broadcasts. Grove sends these cache notifications **after** successful activation/deactivation, only when the installed extension advertises the inspected protocol and the socket belongs to the current user. It does not start a router, patch an extension, or overwrite VS Code state. Missing/incompatible clients do not fail an otherwise successful native operation. IPC delivery is best effort; it is not an acknowledgement that a visible VS Code window has refreshed. Windows named-pipe notification support is not implemented.

Claude Code 2.1.285's published extension maintains `hiddenSessionIds` in VS Code `globalState` and updates its session list through internal webview requests. The inspected implementation does not expose that archive/refresh operation to external tools. Grove therefore retains the existing protection against rewriting Claude's files while its client is running. It does not claim automatic Claude sidebar refresh. Both tools get an Open in VS Code link on the active endpoint; Claude uses the documented `vscode://anthropic.claude-code/open?session=...` handler, which requires the matching workspace to be open. This can open an activated conversation without restarting the IDE, but does not add external deactivation support.

References: [Codex app-server lifecycle](https://learn.chatgpt.com/docs/app-server), [Claude VS Code URI handler](https://code.claude.com/docs/en/vs-code#launch-a-vs-code-tab-from-other-tools). The Codex IPC adapter is based on the inspected extension, not a documented public API.
