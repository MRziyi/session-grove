# Workspace and sync (0.10)

## One Sync action

The banner has one Sync button. A manual sync reads the server catalog and previews
Pull and Push work, then pulls remote changes before pushing local changes. More
than 2,000 pending records or 32 MiB of new local data requires confirmation. The
dedicated progress dialog shows the active direction, counts, progress and estimated
remaining time. The banner keeps a compact progress display; direction arrows do
not rotate. Only the circular Sync icon rotates.

Ordinary local captures and dirty-only automatic sync retain the configured timers.
Large automatic pushes pause for review. No changes means no periodic upload.
Local projects remain browsable during unrelated background transfers. Manual
sync has an exclusive progress view, with server-side writes blocked until it ends.
ETA is an estimate based on completed work; large individual records and network
variation can make early estimates inaccurate.

## Continuous project browser

Projects are a directory for one continuous content list, not isolated pages.
Groups sort by their latest visible conversation, then sessions sort within each
group. Each project initially shows five trees/sessions and can expand. The left
directory follows the visible group. Current Active and Archive stay pinned;
only the project directory scrolls. A project's Select all includes its collapsed
rows, with a visible selected count before archive/move.

Both navigation panes can collapse when reading a session. Drag the separator
between Transcript and Graph, or focus it and use arrow keys, to change proportions.
These preferences are local to the browser. Selecting the same single chat twice
clears the range. The shorter tool badge is **Claude**.

## Provenance, background sessions and archive

Background classification uses native source, thread-source, sidechain and explicit
origin/session-kind metadata; titles and prompt wording do not determine ownership.
Custom Claude titles take precedence over automatic titles. Source shows the native
title's origin. All 32 existing top-level Claude transcripts in the local audit have
human-origin messages; their automatic titles are not evidence of subagents.
Nested Claude subagent logs remain companion artifacts of their parent and are not
promoted into separate native main sessions.

Confirmed scheduled/background records live in **Scheduled & background**, hidden
with the existing settings checkbox. When shown they can be selected and archived
as a group. Explicitly managed background archives remain eligible for sync even
when subsequently hidden.

`scripts/archive-old.js LIBRARY --apply` snapshots the library and Codex state,
refreshes local history, uses a calendar-two-month cutoff on recorded conversation
activity, protects newly created forks, and rechecks revisions before applying.
Codex uses the official `thread/archive` API rather than rewriting a live client's
database. Archive journals record affected native IDs. A failed batch attempts
native unarchive rollback. Claude still uses journalled file materialization with
its native process guard. Archiving retains the records and shared-prefix history.

## Storage and performance

Cloud directory schema **5** introduces content-addressed record packs: up to 256
records or approximately 2 MiB of source text per pack, with oversized individual
records kept together. Compression runs asynchronously with at most four packs in
flight. Free slots are replenished immediately, so one large pack does not stall
the other three. Each uploaded pack is read back and hash-verified before it is checkpointed
or referenced by a published directory. Downloads validate the pack and every
individual record, and checkpoint verified objects before exposing a complete tree.
Interrupted work reuses completed packs. Whole-sync results are persisted separately
from background catalog checks, so a failed push cannot be disguised by a later
successful check. Large-object deadlines scale with size and remain cancellable. Project indexes and the device head publish
only after their dependencies succeed. Moving a tree also updates its previous
project index, including trees imported from another device.

**Other devices must upgrade to 0.10 before reading newly packed data.** This version
continues to read older per-record cloud data and preserves old files/heads; old
clients fail closed on schema 5. Encryption and the saved destination are unchanged.

Immutable summaries persist in SQLite. Startup no longer rewrites every unchanged
entity. Family roots are indexed, and merge validation checks each referenced object
once instead of repeatedly concatenating all historical revisions. Transcript
sections use browser content visibility to avoid painting off-screen sections.
In the personal-library audit, warm startup was about 45 ms, state projection 50 ms
and process RSS 96 MiB before a full transcript was opened. Large transcript/transfer
work still allocates more memory; these are phase-specific measurements.

## Verification

```sh
pnpm test
node scripts/ui-010-smoke.js http://127.0.0.1:9231
node scripts/claude-smoke.js /path/to/claude-home
node scripts/codex-fork-smoke.js /path/to/codex-home THREAD_ID --codex /path/to/codex
node scripts/archive-smoke.js /path/to/codex
node scripts/conversion-smoke.js /path/to/codex
```

The browser fixture exercises 20 projects, list limits, scroll synchronization,
pinned groups, collapse/resize, range toggling, large-transfer confirmation and
completion. Native tests compare 111 Claude checkpoints and a real Chrono fork
(919 model-history records), and reopen a fork after archiving its parent. These
are record/reader equivalence checks without model requests, not a claim that model
internals, dynamic external files, permissions or future responses are identical.
Full cross-agent conversion preserves source JSONL as an archive; lean conversion
deliberately omits/truncates the documented material and retains provenance.

For a persistent local service, use `node bin/session-grove.js --background`.
`pnpm status` and `pnpm stop` manage it; its private log is `logs/server.log` under
the library. Foreground `pnpm start` still stops with Ctrl+C.

Additional audit fixes: Claude continuation now preserves the complete physical
UUID chain after native fork materialization, remapping only the graph boundary;
old revisions remain available. Small tool previews are detached from large V8
strings, and large transient parse caches are released after graph projection.
On the same 49-path tree, retained JavaScript heap after collection fell from about
344 MiB to 27 MiB. Upload checkpoints no longer trigger whole-library redraws, and
hidden tabs suspend event streams. Shared revision reference arrays can be encoded
losslessly in cloud manifests; the local original records remain unchanged.
