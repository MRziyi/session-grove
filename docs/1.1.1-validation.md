# 1.1.1 validation

## Naming

The previous scheduler used discovery flags plus “Ungrouped root” eligibility. A seen, filed or forked session could therefore never receive a model name. Session eligibility now depends on whether a successful model result is recorded. Normal archived sessions can receive a name; trashed, synthetic and background/agent-owned records are excluded. Naming now belongs to each logical Session (tree or standalone), using its beginning; transcription paths have a separate opt-in lifecycle.

A second defect concerned annotation lifetime: one automatic label covered a long segment, then a new fork split that segment into multiple nodes. Both pieces inherited the old title. Automatic annotations now record their chat-range hash and naming evidence hash. A changed range can be renamed; manual names are not automatically replaced. Legacy annotations of unknown ownership are preserved unless explicitly selected for repair.

A real-library snapshot backfill was exercised with an offline model stub: 149 naming requests, eight sessions waiting for their own complete exchange, no pending jobs after the eligible work completed. Assertions compare every pre-existing branch head, parent and project and preserve every established manual title. Separate actual-model verification used only the user-authorized naming evidence; private payloads and results remain outside Git.

Regressions cover filed/previously seen sessions, native and Grove forks, inherited-name provenance reset, manual changes during requests, same-text manual confirmation, matching request/reply pairs, metadata-only messages, auto-node subdivision, API failure/retry, configuration changes and concurrency limits.

## Inline editing and Source

Chrome tests exercise actual pointer double-clicks on navigation project names, project categories, session rows and graph node titles. They verify check-mark save, outside-click and Escape cancellation, empty-name rejection, stale-version rejection and no unintended session navigation during double-click. Source is checked for a visible border, labeled fields and absence of unexplained `unknown` text. The same suite passed against the real-library snapshot with no browser exceptions. Existing graph, sync and drag suites remain in the acceptance run; the new suite also runs in Windows CI.

The local acceptance run passed 283 regression tests, with two Windows-only checks skipped on macOS, plus all four browser suites. Model calls are mocked in public CI; it neither reads nor uploads personal transcripts. Live naming is a separate explicitly authorized operation, preserving a pre-upgrade backup and recording model provenance without altering transcript bodies.


## Login startup controls

Settings toggles a user LaunchAgent on macOS or a current-user Windows Startup shortcut. Generated entries carry the current executable, repository entry point, library/native roots and port. The running service is neither unloaded nor stopped. Each custom library has a separate entry; demo mode and unsupported platforms reject changes. Unknown entries and symbolic links are preserved.

Tests exercise macOS XML/path escaping, enable failure rollback, Windows argument quoting and staging outside the Startup directory, unsupported/demo behavior, concurrent saves, authenticated API access, continued service availability, and browser toggle/error rollback. On Windows CI an actual COM shortcut round trip runs in a temporary directory rather than the user's Startup folder. Generated macOS plists pass `plutil -lint` without installing a login item. The switch is off when no managed startup entry exists, and the UI exposes Enabled/Disabled/Updating/Failed states.

The startup switch defaults to Disabled and uses explicit Enabled, Disabled, Updating and Failed states. The two Windows-native checks are skipped on the macOS acceptance machine and run in Windows CI.

## Independent transcription titles

The installed Codex VS Code 26.928.40906 client was inspected for `thread/name/set`, `thread/name/updated` and its query-cache invalidation handler. The official [App Server API](https://learn.chatgpt.com/docs/app-server) persists thread names. A separate app-server process does not notify an existing process directly, so the compatibility adapter invalidates the installed extension's recent-conversation and search caches through its existing IPC. This adapter is version-sensitive and disabled when its required capabilities are absent; Windows live refresh is not enabled.

A disposable thread in the actual local Codex environment verified official rename/readback, three live cache invalidations, independent Grove Session naming and an unchanged transcript hash. The thread was then removed with the official delete API. This proves persistence and refresh delivery; no visual VS Code screenshot assertion is claimed. No personal thread was renamed by this probe, and no model request was made.

Regressions cover default-off baseline, tail edits, forks, compaction boundaries, concise assistant evidence, cached retry after native failure, concurrent identical paths sharing one request, missing-client deferral, manual native edits and rollback. Browser coverage additionally verifies stable Session headings across path changes, native titles in the picker, no rename tooltip, and change-type-before-time Source rows.

Compaction regression covers completed-node naming on a standalone path, no repeated requests from tail appends, and preserving a manual label across the next compaction. Windows verification failures restore the prior shortcut; native CI also checks real COM creation/readback with a 30-second PowerShell startup allowance.

Browser regression holds a deep reading position while another Session is renamed, the current tree receives a node title, new native-format messages append and Update runs. It asserts stable message identity/offset, selected node and graph camera, and unchanged transcript DOM for unrelated edits. Empty-continuation deactivation retains focus on its surviving parent. Windows PowerShell scripts use encoded arguments and close stdin explicitly; native COM roundtrip passed in Windows CI.
