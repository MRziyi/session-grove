# 1.1.1 validation

## Naming

The previous scheduler used discovery flags plus “Ungrouped root” eligibility. A seen, filed or forked session could therefore never receive a model name. Session eligibility now depends on whether a successful model result is recorded. Normal archived sessions can receive a name; trashed, synthetic and background/agent-owned records are excluded. A fork with no human/assistant exchange after its inherited prefix waits for evidence.

A second defect concerned annotation lifetime: one automatic label covered a long segment, then a new fork split that segment into multiple nodes. Both pieces inherited the old title. Automatic annotations now record their chat-range hash and naming evidence hash. A changed range can be renamed; manual names are not automatically replaced. Legacy annotations of unknown ownership are preserved unless explicitly selected for repair.

A real-library snapshot backfill was exercised with an offline model stub: 149 naming requests, eight sessions waiting for their own complete exchange, no pending jobs after the eligible work completed. Assertions compare every pre-existing branch head, parent and project and preserve every established manual title. Separate actual-model verification used only the user-authorized naming evidence; private payloads and results remain outside Git.

Regressions cover filed/previously seen sessions, native and Grove forks, inherited-name provenance reset, manual changes during requests, same-text manual confirmation, matching request/reply pairs, metadata-only messages, auto-node subdivision, API failure/retry, configuration changes and concurrency limits.

## Inline editing and Source

Chrome tests exercise actual pointer double-clicks on navigation project names, project categories, session rows and graph node titles. They verify check-mark save, outside-click and Escape cancellation, empty-name rejection, stale-version rejection and no unintended session navigation during double-click. Source is checked for a visible border, labeled fields and absence of unexplained `unknown` text. The same suite passed against the real-library snapshot with no browser exceptions. Existing graph, sync and drag suites remain in the acceptance run; the new suite also runs in Windows CI.

The local full regression run passed 271 tests with two Windows-only skips. Model calls are mocked in public CI; it neither reads nor uploads personal transcripts. Live naming is a separate explicitly authorized operation, preserving a pre-upgrade backup and recording model provenance without altering transcript bodies.


## Login startup controls

Settings toggles a user LaunchAgent on macOS or a current-user Windows Startup shortcut. Generated entries carry the current executable, repository entry point, library/native roots and port. The running service is neither unloaded nor stopped. Each custom library has a separate entry; demo mode and unsupported platforms reject changes. Unknown entries and symbolic links are preserved.

Tests exercise macOS XML/path escaping, enable failure rollback, Windows argument quoting and staging outside the Startup directory, unsupported/demo behavior, concurrent saves, authenticated API access, continued service availability, and browser toggle/error rollback. On Windows CI an actual COM shortcut round trip runs in a temporary directory rather than the user's Startup folder. Generated macOS plists pass `plutil -lint` without installing a login item. The switch is off when no managed startup entry exists, and the UI exposes Enabled/Disabled/Updating/Failed states.

The startup switch defaults to Disabled and uses explicit Enabled, Disabled, Updating and Failed states. This candidate remains local for user review; the two Windows-native checks are present in the suite but are skipped on the macOS acceptance machine, and will run in Windows CI after publication is authorized.
