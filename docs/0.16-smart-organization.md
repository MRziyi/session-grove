# Smart organization

Two independent, initially disabled switches use `gpt-6-luna`: name normal sessions (including existing and filed sessions and forks), classify new eligible Ungrouped roots, and name branch points. An API key is required. Saving a new key verifies it before replacing the existing key. Keys and switches live in the local library's `intelligence.json` (mode 0600 on Unix; a restricted current-user ACL on Windows), outside Git export. Public settings report only whether a key exists. A saved key disables the input and replaces Verify with Remove key. Removing the key restores entry and verification, disables both options and cancels pending work.

## Triggers and ownership

- Since 1.1.1, enabling session naming queues every normal session without a recorded model naming result. Previously seen/filed sessions and forks are included. Manual titles remain authoritative; their model result is recorded without replacing the chosen name. Existing node labels with unknown ownership are preserved.
- A new Ungrouped root remains eligible while it is empty or waiting for its first real assistant text. Other sessions use their first human request and its matching reply; a fork waits for its own exchange after the inherited prefix. Metadata such as an open-Page context is excluded. Classification sends the full first human request, available project IDs/names, and the last two components of the working directory as a separate hint. Existing broad categories are preferred. Clear unmatched subjects can create projects; ambiguous requests stay Ungrouped.
- A node becoming a branch point with more than one child is eligible once. Naming uses that node's first human request and last assistant text, drawn from the same actual path. It does not use descendants. Missing evidence leaves the node unnamed. Automatic annotations record the exact chat range and evidence fingerprint. When a later fork splits that range, affected automatic titles are generated again from the smaller node; manual annotations are preserved.
- Model results only change Grove metadata. Native IDs, original titles, transcript records and context policies are untouched. Manual names and project moves made while a request is pending win. Node membership and evidence are checked again before applying a result. Relevant changes update modified timestamps and the Push queue.

## Human-message extraction

Codex naming reads actual `response_item` messages, excluding developer/system roles, reasoning, tool results and directed assistant messages. Legacy event-only user text is a fallback. Known leading environment/plugin wrappers, AGENTS instructions and IDE boilerplate are omitted; the full `My request` body is retained.

Claude naming reads prose text blocks only. `isMeta`, `isCompactSummary`, sidechains, nonhuman user origins, API errors, command echoes and tool-result blocks are excluded. Known IDE metadata blocks are stripped. This is a naming-only projection: arbitrary user-authored XML is preserved and stored transcripts are never cleaned or rewritten.

User text is never truncated. Assistant text over 6,000 Unicode code points retains its beginning and end with an explicit omitted-middle marker. Oversized requests fail visibly rather than silently truncating the user's input. Node prompts request 2–4 words or 4–10 Chinese characters in the human request's language, with a 32-character output limit. They describe the node's topic or established result, without inventing completion or summarizing future work.

## Requests and visibility

The server uses the [Responses API with strict structured output](https://developers.openai.com/api/docs/guides/structured-outputs) and [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna). Requests set `store: false`, have a 45-second timeout and 1,024 output-token budget, and expose no tools. Project choices are constrained to IDs supplied in the request and revalidated locally. Provider error bodies are not echoed to the UI or logs.

A persistent metadata queue runs at most two requests concurrently by default. Settings accepts one (serial) through four concurrent requests and a minimum interval of 0–60 seconds between request starts, shared by all slots. The default interval is zero; the small scheduling yield is not a one-second rate limit. Changing scheduling limits affects subsequent starts. Ordinary Update finishes without waiting for OpenAI; local editing remains available. Metadata application waits for local capture/Trash to release the store and rechecks current names and project membership. Turning off a switch, removing the key or stopping Grove aborts all in-flight requests and suppresses late results. Failures retain their jobs and pause new starts until Retry rather than repeatedly making paid requests. The toolbar and Settings show the actual activity or a labeled queued state, affected sessions, active count, remaining count (including in-flight work) and actionable errors.

## Local evaluation, 2026-09-30

Read-only snapshots supplied 58 sampled native histories, including Codex and Claude. Fifty-one had identifiable human/assistant evidence within the sampled prefix (41 unique first requests). Full real graph snapshots supplied six branching-node examples for naming. Private prompts and full response text were kept outside the source repository.

Classification initially used only the request and project names: three of six selected samples matched their current project, two were incorrectly assigned, and one abstained. Adding a short working-directory hint matched all six. Four additional samples exposed unnecessary creation of a product-specific project instead of an existing broad category; the final prompt explicitly prefers suitable broad categories. A final replay matched all ten sampled project assignments. Because these examples informed prompt revisions, this is a small regression result, not an independent accuracy estimate or a guarantee for future sessions.

The final ten classification requests took 1.38–2.61 seconds each in this run. Six node requests took 1.59–1.84 seconds. All six used the human request's language: five Chinese titles had 7–9 characters and one English title had three words. On three shared examples, a generic short-title prompt produced 13/19/12-character titles; the constrained prompt produced 8/8/7-character titles. Manual review checked relevance, language, brevity and unsupported completion claims. Sampling did not establish the same naming quality for every Claude fork shape; extraction and scheduling behavior are covered separately by fixtures and browser tests.
