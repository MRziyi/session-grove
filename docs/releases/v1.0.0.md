Session Grove 1.0 brings the project/session workflow to Windows, with native Codex and Claude history support and private Git synchronization.

- Fix Windows native executable discovery, process checks, exclusive file checks, background process windows, and repeated native RPC shutdown.
- Smart Organization disables the API key field after saving and replaces Verify with Remove key. Removing the key restores entry and verification, disables both options and cancels queued work. Windows key files use a restricted ACL.
- Smart Organization defaults to two concurrent requests, with a configurable limit of 1–4 and a shared minimum request-start interval of 0–60 seconds. Queued progress always carries an activity label. The header is shorter and the About footer has more space.
- Avoid repeated linear searches during native discovery. An unchanged Pull performs one remote reference check, skips fetch and reuses saved session indexes. Metadata-only Push keeps transcript files unchanged.
- Group session writes into SQLite transactions, stream Git records and yield during large directory imports. The 400-session creation benchmark improved from 38.6 s to 1.9 s; initial-import event-loop delay fell from about 593 ms to 89–95 ms in the local test workload.
- Adjust Codex context/compaction settings and Claude auto-compaction windows from Settings, with profile awareness, preserved unrelated settings and private backups.
- Rewrite both READMEs around project workflows, with fresh screenshots of the real interface using synthetic sessions.
- Add Windows to the Linux/macOS CI matrix, run Windows browser acceptance, and gate releases on all three platforms passing.

Windows validation includes live local discovery and cloud Pull, activation/deactivation/reactivation, compaction choices, all three conversion modes, native fork comparison, and real smart classification/naming requests. See [validation and resource measurements](https://github.com/MRziyi/session-grove/blob/v1.0.0/docs/1.0-windows-validation.md) for the sample sizes, evidence and fidelity boundaries. Model requests are not guaranteed to be identical across clients or agents.
