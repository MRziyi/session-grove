Session Grove 1.0.2 fixes unused-continuation deactivation and makes discard/recovery flows complete and observable.

- An unused continuation activated at an intermediate turn boundary can now be deactivated even after client settings metadata was appended. New turns, unfinished tools, malformed records and changed file bytes retain their protections. Removing the empty graph placeholder does not create a Trash entry.
- Discard shows its current phase. Only required native deactivation presents a target and Confirm button; confirmation completes deactivation and rollback together. Updated selections, related deletion markers and shared project metadata are handled automatically, while unrelated edits in other sessions are preserved. Existing operations are awaited instead of requiring manual retries. Local Git history can recover verified snapshots when a working cache was overwritten, without fetching or pushing.
- Pending uploads uses visible Select all / Deselect and Discard controls. It has no close icon, selection-count label, static explanatory paragraph or filesystem path. The hover menu sits flush below the banner, with one compact target/Confirm row.
- Client archive and Trash are separate views. Trash Restore creates visible sessions in Projects, without activation or a client archive entry. Move to Trash backs up before safely removing deactivated native copies; blocked shared-prefix/file cleanup remains explicit and retryable. Neither archive-only content nor recovery files are uploaded.
- Current Active and Trash stay fixed around a bordered, scrollable Projects container. Outer/group spacing is consistent, the empty Client archive entry is hidden, and banner/page headings are more compact. Long sync errors expand without stretching the banner.
- Browser checks wait up to 45 seconds for a live debugging endpoint instead of asserting after 10 seconds, addressing slow Windows runner startup. Scroll-boundary checks now allow the browser's legitimate maximum-scroll clamp while retaining the requested project selection.

The v1.0.1 release-tag workflow succeeded, but the separate main workflow failed its Windows browser startup assertions. A successful release job does not erase those failures or their notification emails. For this release, main CI is checked before creating the version tag, and the tag's test-gated release workflow is also checked through publication.
