# 0.15.1: node context and native identity

Names are display metadata. Grove's alias is separate from the observed native title. Update reads titles by native thread ID, refreshes the transcript selector, and leaves the Grove alias and original files unchanged. The initial alias is seeded from the imported title; later client renames do not overwrite it.

A native turn can include one user message, several assistant messages, tools and a final completion event. Grove nodes may end between these messages. Activation now accepts an explicit node boundary when the copied prefix has no unresolved tool calls. It preserves exactly the selected prefix and creates a separate continuation at every position, including the root and endpoint; it never includes subsequent visible messages or their duplicate native text events. Original records remain immutable. Malformed/incomplete tool exchanges still cannot be materialized as a valid native conversation.

Older Codex native forks sometimes received a zero-length shared prefix because the native writer serializes an absent optional `reasoning.content` as `null`. Key order and this optional default are normalized when comparing history. Existing trustworthy native links are repaired during Update; the graph also shares their exact visible prefix and maps existing annotations to the shared identity. This does not deduplicate unrelated sessions by title.

## Native comparison

`scripts/node-fork-equivalence.js LIBRARY BRANCH_ID` reads the selected history and creates isolated temporary native stores. It invokes the installed Codex app-server and the official Claude SDK 0.3.283 without model requests or changes to the original library/native files.

The selected real Codex history produced 400 model-history items on both sides (Codex 0.155.0-alpha.16.3) at a completed intermediate turn. The sole payload difference was the optional reasoning content field (`null` vs absent). After that normalization, model history, prompt metadata and recorded world state matched. A Grove prefix ending at the actual Round 2 polish intermediate commentary node was also accepted by native `thread/resume` and retained precisely its selected model-history records.

Codex's installed `thread/fork` schema accepts `lastTurnId` and explicitly disallows an in-progress turn. An arbitrary message boundary therefore is **not exactly the same operation** as that native fork. Grove adds finer context selection; it does not claim identical model responses or runtime state. Raw files also differ in generated IDs, timestamps, titles and native bookkeeping.

Claude comparisons at 1-, 2- and 3-message boundaries matched official `forkSession(..., upToMessageId)` message payloads and normalized records, excluding generated IDs/timestamps. These checks validate the tested file/SDK behavior, not hidden model state or future responses.

## Interaction

Status and measurements remain to the left of the aligned Pull/Push/Update controls. Progress fills the buttons. Settings cards use balanced internal spacing, with the collapse interval label and selector on one row. Clicking outside a dialog dismisses it. Active node dots occupy the lower-right corner, leaving the upper-right for tool identity.

Session navigation keeps the existing view visible until the new context is ready, then fades in the replacement. The session rail shares project folding with the list, selects the current project, and preserves scroll state on return. Transcript-to-node ribbons remain visible whenever the node left-edge anchor is visible, even if its right edge is clipped.
